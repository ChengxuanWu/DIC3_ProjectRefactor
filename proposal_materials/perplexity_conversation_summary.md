# Perplexity 對談紀錄與重點整理：實價登錄與 LLM 房地產決策系統（A–F 論證素材）

> **核心論點**：實價登錄是高價值但**非全市場母體**、且**單價計算口徑高度敏感**的資料源；因此，LLM 房價決策系統不能僅給出單一黑盒子數字，而必須透過**確定性工具計算（Whitelisted Tools）**、**版本化知識檢索（RAG）**、**ReAct 推理迴圈**與**證據閘門（Evidence Gate）**，將「價格口徑、資料限制與證據來源」轉化為可審計的決策支援。

### 2. 核心金句（可直接引用於簡報／論文）
> 「內政部官方案例顯示，同一筆 3,000 萬元、80 坪的交易，因車位、共同使用部分與附屬建物的計算方式不同，單價可介於 37.5 萬至 56 萬元／坪；因此，住宅決策系統不能只輸出一個平均單價，而必須揭露價格口徑、資料限制與證據來源。」

## 二、Perplexity 完整對話內容存檔（Full Conversation Archive）

以下把最新可引用的官方資料、研究與案例整理成可直接放入 A–F 的論證素材。核心訊息是：實價登錄是高價值但非完整、且單價口徑敏感的資料源；LLM 房價決策系統必須以工具化計算、版本化知識檢索與證據閘門來控制不確定性與幻覺。

### A. Attention Getter：實價登錄不是全市場母體
* 內政部實價登錄揭露的是「申報登錄」的成交資訊，並非所有市場交易；其資料亦採去識別化、區段化方式提供，且涵蓋房地、純土地、純建物、車位及預售屋等不同交易類型。因此，把它直接視為全市場母體，會忽略未申報、申報時點落差、非住宅交易混入及不同標的型態的差異。
* 內政部官方查詢網明確指出，均價是「交易總價加總 ÷ 移轉總面積加總」，且預設交易標的為「房地（土地＋建物）」；若未進一步篩選建物型態，店面也會被納入，平均單價因此可能被拉高。這正好支持你的切入點：一個「平均單價」不能直接當作住宅市場的乾淨價格訊號。（參考：[內政部不動產交易實價查詢服務網](https://lvr.land.moi.gov.tw/jsp/index.jsp)）

#### 車位與面積的官方案例
內政部地政司提供了一個極具說服力的官方數字案例：總價 3,000 萬元、建物移轉總面積 80 坪、其中車位價 200 萬元與車位面積 10 坪的交易：

| 計算口徑 | 單價 |
| :--- | :--- |
| 含車位總價 ÷ 總面積 | 37.5 萬元／坪 |
| 剔除車位價與車位面積 | 40 萬元／坪 |
| 再剔除共同使用部分 | 46.67 萬元／坪 |
| 再剔除附屬建物 | 56 萬元／坪 |

* 同一筆交易，因為是否扣除車位、公設與附屬建物，單價可從 37.5 萬元／坪擴大到 56 萬元／坪，差距約 **49%**。這可作為開場的具體數字鉤子：若系統只回一個「每坪多少萬」，而未揭露單價口徑，便可能誤導住宅決策。（參考：[內政部地政司](https://www.land.moi.gov.tw/chhtml/content/10?mcid=3636)）
* 內政部也說明，若申報人未提供車位價格與車位面積，交易單價會以「房地總價 ÷ 建物移轉面積」計算；若有提供，則以「（總價－車位價）÷（建物面積－車位面積）」計算。此外，未辦保存登記、增修建等情形會使登錄面積低於實際使用面積，進一步使單價偏高。

### B. But：黑盒子估價與單一數字的風險

#### 資料品質與制度限制
* 實價登錄資料由權利人或義務人申報，研究已指出其存在人工輸入不一致、欄位缺失、資料登錄時間落後等問題；一項以臺灣實價登錄進行大數據分析的研究，在清洗過程中即因交易類別、主要用途、零值或異常單價等條件，移除大量樣本。這說明你的資料前處理、篩選規則與可追溯紀錄，並非工程細節，而是研究效度的核心。（參考：[臺灣實價登錄大數據分析研究](https://www.tpefx.com.tw/uploads/download/tw/202501103.pdf)）
* 臺中市政府地政局提供的「110 年後買賣案件」資料集，欄位即包含建物移轉總面積、總價、單價、車位類別、車位移轉總面積、車位總價、備註與地所狀態等；這些欄位正是判斷「同一社區、同一總價，為何單價不同」的關鍵。你的 32 欄、9,152 筆住宅候選資料，因此有明確的官方欄位基礎可支撐資料品質與口徑檢核。（參考：[政府資料開放平臺 - 臺中市110年後買賣案件](https://data.gov.tw/dataset/103038)）

#### LLM 幻覺與黑盒子問題
* RAG 的研究共識是：將生成內容錨定於可驗證的外部證據，可降低幻覺並提升可追溯性；2025 年 SemEval 的 RAG 幻覺偵測研究也將 RAG 視為透過外部知識檢索降低幻覺的主要途徑。但最新研究同時提醒：RAG 不是萬靈藥；若檢索到的上下文不足、不精確或互相衝突，模型仍可能產生不忠實推論。
* 這正好支持你對「單一估價數字」的批判：即使模型給出房價預測，若未說明資料快照日期、樣本篩選、車位與公設處理、地理範圍、法規有效日期與不確定性，使用者仍無法判斷該數字能否作為決策依據。你的 **Evidence Gate** 因此應要求每個關鍵主張附帶：資料來源、版本／快照日期、計算公式、樣本數、排除條件與信心或適用範圍。

### C. Cure：ReAct + RAG + 白名單工具
ReAct 的價值在於把 LLM 從「一次生成答案」改為「思考—行動—觀察」的互動迴圈：模型可依當前推理狀態決定何時呼叫外部工具，並在過程中取得額外事實資訊，而非只依賴固定的前置檢索。這與你的架構高度契合：模型不應自行心算房價，而應呼叫受控工具完成資料篩選、統計、估價與地圖分析。（參考：[arXiv:2510.24476](https://arxiv.org/html/2510.24476)）

| 系統元件 | 學理依據 | 對房地產決策的意義 |
| :--- | :--- | :--- |
| **ReAct** | 互動式 reasoning–action–observation 迴圈，可動態呼叫外部工具 ([arXiv](https://arxiv.org/html/2510.24476)) | 將「查資料、算單價、檢查法規、產出建議」拆成可稽核步驟 |
| **RAG** | 以可驗證外部知識錨定生成，降低幻覺並提升可追溯性 (ACL Anthology) | 讓法規、實價登錄欄位定義、公告現值等資訊可回溯 |
| **Evidence Gate** | 證據約束生成可降低幻覺式歸因 ([TREC NIST](https://trec.nist.gov/pubs/trec34/papers/ii_research.rag.pdf)) | 無證據即不得宣稱「該區均價」或「此物件合理價」 |
| **白名單工具** | 工具使用可依任務動態調用外部資源，提升複雜任務可靠性 ([arXiv](https://arxiv.org/html/2510.24476)) | 限制模型只能使用核准的資料查詢、統計與 GIS 功能 |
| **確定性程式計算** | RAG 不足以保證數值正確，需明確計算與驗證 ([Google Research](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/)) | 車位、公設、單價、樣本統計皆由程式碼計算，不由 LLM 推算 |

### D. Development：把「口徑」變成可稽核契約
你的系統應將內政部官方單價規則直接寫入程式化工具，而非讓 LLM 自由解讀。內政部明定：含車位但未申報車位價格與面積時，以房地總價除以建物移轉面積；有申報時，則扣除車位價與車位面積後計算。

建議在系統中建立三層輸出：
1. **資料契約**：標示資料集版本、快照日期、原始筆數、住宅篩選後筆數、排除規則與欄位缺失率。
2. **計算契約**：明列單價公式、是否扣除車位、公設、附屬建物，以及樣本數與異常值處理。
3. **決策契約**：將價格、建物型態、坪數、屋齡、行政區、法規限制與不確定性並列呈現，而非只輸出單一估價。

這能直接回應內政部揭示的問題：同一交易可因車位、共同使用部分與附屬建物的處理方式，產生 37.5 萬至 56 萬元／坪的不同單價。換言之，你的系統不是「更會算房價」，而是把價格口徑、資料限制與證據來源變成使用者看得見的決策條件。（參考：[內政部地政司](https://www.land.moi.gov.tw/chhtml/content/10?mcid=3636)）

### E. Experiments：以臺中官方快照建立可重現評測
* 臺中市政府地政局已公開「110 年後買賣案件」實價登錄資料，包含標的位置去識別化、面積、總價、車位類別、車位總價等欄位，並提供 115 年 1 月 1 日至 3 月 31 日的 CSV 資源。因此，你取得的 115 年第 3 季 10,638 筆、32 欄快照，具有官方資料源與明確欄位定義，可作為可重現實驗基礎。（參考：[政府資料開放平臺 - 臺中市110年後買賣案件](https://data.gov.tw/dataset/103038)）
* 建議將實驗設計明確分為三個可審查層次：
  1. **時間外推**：以較早月份或季度訓練、較晚期間測試，檢驗模型是否只是記憶歷史成交。
  2. **空間分層**：依行政區、都市計畫分區、生活圈或地理群集切分，避免同一社區同時出現在訓練與測試集。
  3. **REAL 基準**：建立「真實、可解釋、可審計、可重現」的評測集，並誠實標記為 `PLANNED` 或 `NOT RUN`，避免把規劃中的結果寫成已完成發現。
* 臺中市也提供「實價登錄每季動態分析」，其中包含公寓、華廈、住宅大樓平均單價及透天厝平均總價等指標，可作為系統輸出的外部 sanity check，而非直接當作預測真值。此外，臺中已上線 3D 實價登錄，提供價格與位置資訊，未來將配合國家 3D 智慧國土計畫擴充建物資訊；這可作為 GIS 條件式啟用的政策與資料基礎。

### F. Findings：不宣稱消除幻覺，而是可審計的決策支援
* 最新研究支持你的保守主張：RAG 能降低幻覺、提升證據可追溯性，但效果取決於檢索證據是否充分、準確且一致；Google 的研究也指出，RAG 幻覺可能源於上下文不足，而選擇性生成可緩解此問題。因此，你的預期產出不應是「保證優於固定流程」或「消除所有幻覺」，而是建立一個**失敗可見、證據可查、計算可重現**的決策支援原型。
* 建議將預期發現寫成以下形式：
  * 建立具白名單工具與 Evidence Gate 的 ReAct＋RAG 房地產決策支援原型。
  * 產出資料可追溯表示法，記錄官方資料版本、快照日期、篩選規則、計算口徑與證據連結。
  * 以臺中 115 年第 3 季官方 CSV 快照建立時間外推、空間分層與 REAL 評測設計；所有未執行項目誠實標記為 `PLANNED`／`NOT RUN`。
  * 將「單一估價」改為「價格區間、可比案例、口徑說明、法規限制、資料缺口與建議行動」的結構化決策輸出。
